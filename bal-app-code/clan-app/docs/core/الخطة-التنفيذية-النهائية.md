### 1.2 الهوية المعتمدة (من جلستي التصميم + مرجع المالك)
- **اللغة البصرية**: Cinematic Floating Soft-Depth UI — شاشة = مشهد بطبقات، مش Cards مكدسة

- **الألوان**: ✅ أخضر جبلي × قمري (داكن `#0F1B14` + `#3DD68C` / فاتح `#F4F9F5` + `#1FA268`) — **⚠️ قرار معلق: الصورة المرجعية بنفسجية — هل نتحول لغروب بنفسجي؟**
- **الخط**: IBM Plex Sans Arabic + IBM Plex Sans
- **الثيم**: داكن + فاتح (تلقائي/يدوي) · **الزوايا**: دائرية جداً (16–28px)
- **الأصوات**: ساكت (المنبه والرسائل فقط) · **الحركة**: ناعم 200–350ms + Staggered
- **البوب أبات**: Sheet زجاجي من تحت للمعلومات/الإجراءات + Dialog زجاجي صغير للتحذير
- **الأزرار**: Pill رئيسي · Outline ثانوي · Circular أدوات · Hero FAB (+) في الناف بار · Morphing للسياقات
- **اللغات**: 13 (ar RTL + en/de/fr/it/es/tr/pt-BR/ru/id/pl/nl/ja) بنظام i18n من اليوم الأول

## الجزء 2: خطة شاشة الجبل 🏔️ (UX-1 — أول ما نبدأ)

### 2.1 الربط الحي بالباك (مسارات موجودة ومختبرة فعلاً)
| الاستخدام | المسار الحقيقي |
|-----------|----------------|
| إنشاء الحلم (الجبل الجديد) | `POST /api/goals/dream` `{ title }` |
| كويز الـ AI للخطة | `POST /api/goals/dream/:id/answers` |
| الموافقة على الخطة | `POST /api/goals/dream/:id/approve` |
| قائمة الأهداف (الجبال) | `GET /api/goals/` |
| تفاصيل الهدف + خطواته | `GET /api/goals/:id` |
| إتمام خطوة (ترتيب صارم — 400 لو غلط، 409 لو مكرر) | `POST /api/goals/dream/:goalId/steps/:stepId/complete` |
| إتمام الهدف كامل (وصول القمة 🏁) | `POST /api/goals/:id/complete` |
| تسمية الرفيق | `PATCH /api/auth/companion` |
| رسالة الرفيق (كلامه في الشاشة) | `POST /api/ai/message` + `stream` |

### 2.2 الشاشة — 7 طبقات (بالترتيب من الخلف للقدام)
```text
1. Background     : سماء ليلية متدرجة + نجوم خافتة (أو نهارية في الثيم الفاتح) — CustomPaint
2. Ambient        : توهج ناعم حول القمة + ضباب خفيف متحرك
3. Hero           : الجبل نفسه — JourneyPath (منحنى عضوي) + StageNodes + علم القمة
4. Content        : MetricCard (نسبة التقدم) + GlassCard (المرحلة الحالية + كلام الرفيق)
5. Floating Cards : ActionCards (خطتي / إنجازاتي / إحصائياتي / اقتراح AI)
6. Floating Acts  : FloatingActionStack جانبي (عند الحاجة) + AICompanionOrb
7. FloatingNavBar : جزيرة طافية + Hero FAB (+) → Create (مهمة/تركيز/هدف/منبه)
```

### 2.3 مراحل الشاشة (الحالات)
| الحالة | ماذا تظهر | مصدر البيانات |
|--------|-----------|----------------|
| **Empty** (مفيش جبل) | "الجبل مستني أول خطوة" + PillButton "ابدأ بناء خطتك" | `GET /api/goals/` → [] |
| **معالج إنشاء الجبل** (4 خطوات) | 1) اسم الجبل + الحلم ← 2) كويز AI (أسئلة توليد) ← 3) مراجعة الخطة ← 4) موافقة → الجبل يظهر ويتحرك | dream → answers → approve |
| **الرحلة** (جبل قائم) | المسار + عقد (مكتملة/حالية/مقفولة) + الكروت + الناف بار | `GET /api/goals/:id` |
| **تفاصيل مرحلة** | Sheet زجاجي: وصف المرحلة + "أكملت المرحلة" → Celebration | complete step |
| **القمة** 🏁 | عند آخر خطوة: احتفال كبير (نبضة علم + جزيئات + XP) + الجبل التالي | complete goal |

### 2.4 حركة الدخول (Staggered — بالترتيب)
```
السماء fade ← الجبل يظهر (fade+scale) ← المسار يُرسم (من أسفل لفوق) ←
العقد تظهر تباعاً ← العقدة الحالية تتوهج (Pulse) ← الكروت تنزلق ← الناف بار يطفو ← الـ AI orb
```
- إتمام خطوة: نبضة على العقدة + انفجار جزيئات صغير (CelebrationOverlay) + المسار يتقدم لأعلى
- كل الحركات باحترام `MediaQuery.disableAnimations` (Reduce Motion)

### 2.5 مكونات Flutter المستخدمة (من السجل)
`AppScaffold · JourneyPath (CustomPaint) · StageNode · StagePill · MetricCard · GlassCard · ActionCard · CompactInfoCard · PillButton · BottomSheetContainer · FloatingActionStack · HeroFab · FloatingNavBar · AICompanionOrb · CelebrationOverlay · SkeletonSurface (تحميل)`

### 2.6 خطوات التنفيذ (بالترتيب)
1. إعادة تثبيت Flutter SDK + إنشاء المشروع + الثيم (داكن/فاتح) + الخطوط + i18n (13 لغة، العربية والإنجليزية كاملتين أولاً)
2. بناء مكونات الجرامر الأساسية من السجل (GlassCard، PillButton، HeroFab، FloatingNavBar...)
3. شاشة الجبل (Empty + الرحلة) + JourneyPath + StageNodes
4. معالج إنشاء الجبل (4 خطوات بالكويز والموافقة)
5. إتمام الخطوات + CelebrationOverlay + الوصول للقمة
6. ربط الرفيق (تسمية + Orb + رسائله في الشاشة)
7. **اختبار حي شامل** — كل خطوة من دول مربوطة بالباك ومختبرة فعلياً، مفيش شاشة شكلية

> ملاحظة: شاشات التعارف والتسمية (نفس مرحلة UX-1) تُبنى قبل الجبل في التدفق: تعارف (أسئلة) ← تسمية الرفيق (`PATCH /auth/companion`) ← أول مرة يفتح الجبل (Empty) ← ينشئ جبله.

## الجزء 4: تقنية التوليد والتخزين والتنفيذ (معتمدة من المالك — 2026-08-13)

### 4.1 الـ AI يرجع JSON منظم — مرحلتان فقط (مش خطة سنة)
**المرحلة 1 — Dream/Goal Generator** (نداء واحد بعد الكويز):
```json
{ "dream_title": "Frontend Developer", "duration_months": 12,
  "goals": [ { "title": "تعلم HTML", "weeks": 2 },
             { "title": "تعلم CSS", "weeks": 3 },
             { "title": "تعلم JavaScript", "weeks": 8 },
             { "title": "تعلم React", "weeks": 8 } ] }
```
**المرحلة 2 — Journey Generator** (نداء واحد لكل هدف — عند الموافقة عليه):
```json
{ "days": [ { "day": 1, "title": "مقدمة HTML" },
            { "day": 2, "title": "العناصر الأساسية" },
            { "day": 3, "title": "الصور والروابط" } ] }
```

### 4.2 التخزين — PostgreSQL بسلسلة معرفات
```
Dream       → Goal (موجود)
Goal        → GoalStep (موجود، + durationWeeks 🆕)
GoalJourney → 🆕 (goalStepId unique · title · durationDays · currentDay · status)
JourneyDay  → 🆕 (journeyId · dayNumber · title · description · scheduledDate · status)
```
(الرحلة واليوم مولودان جوه نفس صفقة الموافقة — في قاعدة الحقيقة الوحيدة)

### 4.3 الـ Scheduler اليومي — CurrentDay (صفر AI)
```
كل يوم: Job برمجي
→ SELECT * FROM JourneyDay WHERE journeyId = X AND dayNumber = journey.currentDay
→ ينشئ Task { source: 'JOURNEY', journeyDayId, goalStepId }
→ يظهر في قسم المهام
```
مهمة اليوم مولودة من اليوم الحالي فقط — لما تخلص، اليوم اللي بعده (بعد update currentDay).

### 4.4 قرار المالك: النظام المرن ✅
- اليوم التالي **يفتح دائماً** (مش قفل زي الألعاب)
- لكن بيظهر شارة **«متأخر N يوم»** على الأيام الفائتة
- السحر: تأخر 5 أيام → Follow-up Coach يعرض إعادة بناء الرحلة (21→35 يوم) **بموافقة المستخدم**

### 4.5 التوليد التدريجي للرحلات (قرار المالك ✅)
- عند الموافقة على الحلم: تُولَّد **رحلة الهدف الأول فقط**
- لما الهدف يكتمل 100% → الـ AI يولّد رحلة الهدف اللي بعده
- السبب: المستخدم بيتغير — مفيش خطة جامدة لسنة كاملة

### 4.6 الفصل المعماري (الثبات حتى لو الـ AI واقع)
| الـ AI يفكر ويخطط فقط | التطبيق ينفذ بدون AI |
|---|---|
| Dream Generator | Task Creation |
| Goal Generator | Task Scheduling |
| Journey Generator | Notifications (نكشة/بدء/اطمئنان) |
| Follow-up Coach (إعادة البناء + المتابعة) | Progress Tracking · Day Unlocking · Completion Logic |
