# 🧩 خطة الترابط الكامل — Clan App
**الهدف:** تحويل المشروع من "واجهات شكلية + باك إند معزول" إلى **جسد واحد متلاحم** — كل زر يشتغل 100% (UI → API → DB → تحليلات) زي ما دستور البناء يفرض.
**التاريخ:** 12 أغسطس 2026

---

## 📊 التشخيص — الوضع الحالي (بالدليل)

| القطعة | الحالة | الدليل |
|---|---|---|
| الباك إند | ✅ شغال ومختبر (482+ اختبار) | 100+ مسار REST + Socket.io + 58 جدول |
| الفرونت (Flutter) | 🟠 بيتعرض لكن **معزول** | بيستدعي 6 مسارات بس من ~60 |
| الموبايل أرم | 🔴 **كود نيتيف جاهز لكن مش موصول** | `setNativeAlarm` صفر استخدام + الصوت معلّق في كومنت |
| تسجيل الدخول | 🔴 مش متصل | `main.dart` بيفتح الشل مباشرة — AuthGateway يتيم |
| التنقل | 🔴 مش زي الدستور | الشريط السفلي: [التركيز، منبه المهام، المرافق، العشائر] — ناقص "الرئيسية" و"أنا" |
| شاشات يتيمة | 🔴 5 شاشات | PrestigeVault · RadarAnalytics · UserProfile · AuthGateway · Onboarding |

---

## 🧭 المبادئ الحاكمة (من دستوركم)

1. **الترابط الحي**: كل زر = UI → API → DB → إحصائيات → AI (ممنوع الأزرار الشكلية)
2. **صفر بيانات وهمية**: كل البيانات من الـ API (نشيل BMW X6 الهاردكود)
3. **قاعدة الـ 3 نقرات**: أي ميزة تُفتح في ≤3 نقرات
4. **زيرو إيموجيات + 3 ألوان** في كل واجهة جديدة
5. **الاختبارات قبل التسليم**: كل مرحلة تنتهي باختبارات خضرا
6. **Flutter هو الفرونت الوحيد** (الويب build للمعاينة فقط — والموبايل هو الهدف)

## 🗺️ المراحل — بالترتيب (كل مرحلة تعتمد على اللي قبلها)

### المرحلة 0 — الأساس: المصادقة + عميل API موحد (يومان)
**المشكلة:** التطبيق بيفتح من غير تسجيل دخول، والـ ApiClient ناقص.

| المهمة | الملفات |
|---|---|
| بوابة الدخول: فحص التوكن → لو مش موجود → شاشة تسجيل (Google) → اختيار المجال → الشل | `main.dart` + `auth_gateway_screen.dart` + `onboarding_domain_picker.dart` |
| ربط Google Sign-In (موبايل: `google_sign_in` · ويب: `google_identity_services_web`) | `auth_gateway/` |
| عميل API موحد: refresh تلقائي عند 401 + أخطاء موحدة + كل الدوال (get/post/put/delete/patch) | `core/network/api_client.dart` |
| تطبيق `api_endpoints.dart` على الواقع (شيل الوهمي، ضيف الصح) | `core/network/api_endpoints.dart` |
| حارس onboarded في الفرونت (أي شاشة = لو مش مكمل بيانات → يرجّع للاونبوردينج) | `core/` |

**القبول:** تسجيل دخول حقيقي → جلسة → refresh تلقائي → خروج → إعادة دخول.

### المرحلة 1 — الحلقة الأساسية: المهام + التركيز (3 أيام)
**المشكلة:** الشاشات معزولة عن `/api/tasks` و `/api/focus`.

| المهمة | الملفات | الـ API |
|---|---|---|
| ربط شاشة المهام: جلب/إنشاء/إتمام/حذف/خطوات/ترحيل | `task_timeline/` | `GET/POST /api/tasks` · `PATCH /:id/complete` · `steps` |
| ربط صندوق الفضفضة (حرق الهموم) | `silent_venting_box.dart` | `POST /api/tasks/venting` |
| ربط بناء الدورة → ردهة الفريق → بدء الجلسة → إنهاء | `cycle_builder` + `squad_lobby` + `locked_focus_hud` | `POST /api/focus/start` · `/:id/complete` · `GET /active` |
| كشف الساهي الحقيقي (سؤال مباغت من السيرفر) | `focus_check_modal.dart` | `POST /api/focus/:id/check` · `answer` |
| عرض الشرارات والستريك من الـ API | `home/` | `GET /api/auth/me/stats` |
| إشعار عند فتح وسام (+100 شرارة) | `achievement` | من رد `/complete` |

**القبول:** المستخدم: مهمة → يبدأ تركيز → يكمل → الشرارات تزيد في الواجهة → وسام يفتح.

### المرحلة 2 — منبه المعركة الحقيقي (يومان) 🔴 أهم إصلاح
**المشكلة:** منبه ديمو — جسر نيتيف جاهز غير موصول + مسار باك إند غلط.

| المهمة | الملفات |
|---|---|
| **إصلاح مسار الباك إند**: إضافة `POST /api/alarms/wake-log` (موجودة في المنطق، ناقصة في الراوتر) | `src/modules/alarm/alarm.routes.js` |
| شاشة ضبط منبه → تحفظ في السيرفر → **تستدعي الجسر النيتيف** | `battle_alarm_screen.dart` + `alarm_native_bridge.dart` |
| جلب مسألة الاستيقاظ الحقيقية + إرسال الحل | `alarm_solve_modal.dart` | `GET /api/alarms/wake-task` · `POST /wake-task/solve` |
| تسجيل ساعة الاستيقاظ بعد الحل (النقطة الحقيقية) | `alarm_state_machine.dart` | `POST /api/alarms/wake-log` |
| تشغيل الصوت الفعلي (شيل الكومنت — `alarm.wav` asset) | `core/audio/audio_state_machine.dart` |
| شبكة الأمان: إعادة الجدولة عند فتح التطبيق + بعد الإقلاع | `main.dart` + `AlarmReceiver.kt` (جاهز) |

**القبول:** تثبّت منبه 06:00 → تقفل التطبيق → يرنّ على الهاتف → تحل المسألة → السيرفر يسجّل استيقاظك + شرارات.
