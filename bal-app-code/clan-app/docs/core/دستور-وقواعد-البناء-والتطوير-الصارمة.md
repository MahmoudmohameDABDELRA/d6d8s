# 📜 دستور وقواعد البناء والتطوير الصارمة (System Development Rules)

تعتبر هذه القواعد بمثابة **أوامر معمارية صارمة لا تقبل التجاوز أو الاجتهاد الفردي**. يجب قراءتها والالتزام بها قبل كتابة أو تعديل أي جزء من الكود:

---

### 🛑 Rule 1: الاستئذان والتفويض المسبق (Strict Permission Rule)
* **يمنع منعاً باتاً** اتخاذ أفعال مستقلة، أو التعديل على ملفات رئيسية، أو البدء في كتابة كود لميزة جديدة، أو تغيير معمارية قائمة **إلا بعد طرح الخطة وتلقي إذن وتفويض صريح مني أولاً**.
* عند اقتراح خطة جديدة، انتظر ردّي بـ "موافق" أو "ابدأ" قبل إخراج أو تحديث أي كود.

---

### 📖 Rule 2: المرجعية الموحدة للوثيقة النهائية (The Master Document Rule)
* قبل بناء أو تصميم أي ميزة أو موديول، يجب عليك الذهاب فوراً للوثيقة المرجعية الشاملة للمشروع (`الدستور-المعماري-الشامل-والنهائي-للتطبيق-الحي.md` و `FIXES.md`) ومطالعتها بتمحيص.
* **التنفيذ يجب أن يكون مطابقاً 100% للرؤية والشكل النهائي المحدد في الوثيقة من السطر الأول**، ويمنع تماماً وضع حلول مؤقتة، أو واجهات وهمية (Placeholders)، أو تأجيل الربط لمراحل لاحقة.

---

### ⚡ Rule 3: التجميع الكامل والترابط الحي (Full Integration & End-to-End Wiring)
* **لا تُقبل الأقسام المعزولة أو الأزرار الشكلية:** يمنع منعاً باتاً إنشاء أي زر، أو واجهة، أو قسم لا يعمل بشكل حقيقي 100%.
* **دورة الحياة الكاملة للميزة (End-to-End Cycle):** أي زر أو ميزة تبنيها يجب أن تكون مربوطة ومسمّعة في كل طبقات النظام فوراً:
  1. **الواجهة الأمامية (UI/Client):** تستجيب للمس وتطلق الحدث بفيزياء لمسية 0ms.
  2. **قاعدة البيانات (Database):** تقرأ وتكتب البيانات الحقيقية في الجداول المخصصة عبر Prisma/PostgreSQL.
  3. **الخلفية والسيرفر (Backend & API & WebSockets):** تعالج حزم البيانات والـ JSON Payload وأحداث المقابس الحية.
  4. **لوحة التحكم والإحصائيات (Admin Dashboard & Analytics):** تعكس التغيير والبيانات الناتجة فوراً في `user_stats` و `activity_logs`.
  5. **باقي الأقسام (Connected Modules):** تؤثر الإشارة في قسم الـ AI، والمنبهات، والمهام، والجداول دون أي تفكيك.

---

### 🛡️ Rule 4: عدم قاطع للـ Mock/Fake Data (Production-Ready First)
* يمنع استخدام بيانات وهمية مؤقتة داخل الكود النهائي (Hardcoded / Dummy Data).
* البيانات التي تتحرك داخل الأبلكيشن يجب أن تكون بيانات حقيقية تمر عبر حزم الـ JSON المعتمدة ومرتبطة بحالة المستخدم الحالية (Global State).

---

### 🎨 Rule 5: معايير التصميم المينيمالي الحديث والـ UI/UX الصارم (Modern Minimalist System)
* **منع الإيموجيات تماماً (Zero Emojis):** يُمنع استخدام الإيموجيات في أزرار التحكم، القوائم، أو العناوين، واستبدالها بأيقونات SVG بسيطة (مثل Lucide Icons) عند الضرورة الوظيفية فقط.
* **تناسق الألوان المقتصد (3 Colors Max):** الالتزام بـ 3 ألوان كحد أقصى (لون أساسي، لون محايد للخلفيات والنصوص Grayscale، ولون تمييز خفيف Accent)، مع منع التدرجات الحادة والألوان الفسفورية.
* **الأزرار والمكونات الناعمة:** حواف ناعمة (`rounded-md`)، ظلال خفيفة جداً (`shadow-sm`)، وتصميم مسطح يندمج بانسيابية مع الخلفية.
* **منع الحشو والازدحام (Anti-Bloat):** مساحات فارغة مريحة (Whitespace)، منع الكروت الزائدة أو النصوص الطويلة داخل الأزرار، والتركيز على الوظيفة الأساسية.
* **تسلسل الخطوط ونصوص الإجراءات:** 3 أحجام خطوط كحد أقصى للشاشة، ونصوص أزرار مباشرة ومختصرة جداً ("حفظ"، "تعديل"، "إلغاء").
* **المرجع التفصيلي:** متاح ومحفوظ في `دستور-التصميم-المينيمالي-والواجهات-الحديثة.md`.
