## ٢. قنوات الإشعارات الصوتية وأولوياتها (Notification Channels)

تم تصنيف الإشعارات في ٤ قنوات مستقلة تضمن عدم حجب التنبيهات الحرجة:
1. 🚨 **قناة المنبهات والتحديات (`clan_urgent_alarms`)**:
   * أولوية قصوى (`PRIORITY_MAX` / `apns-priority: 10`)، تتجاوز وضع الصامت للمنبهات الفجرية وتحديات العشيرة.
2. ⏰ **قناة تذكير المهام المسبق (`clan_task_reminders`)**:
   * تطلق قبل موعد المهمة بـ ٥ دقائق مع النغمة المجهزة (`soundTheme` مثل `zen_bell` أو `warrior_chime`).
3. 💬 **قناة المحادثات والعشائر (`clan_messages`)**:
   * إشعارات الدردشة والرسائل المباشرة وطلبات المراسلة.
4. 📢 **قناة الإعلانات العامة (`clan_general`)**:
   * إعلانات الإدارة والتحديثات وتوزيع المكافآت.

## ٣. الكنس التلقائي للتوكنات الميتة (Dead Token Eviction)

* **المشكلة في التطبيقات الأخرى**: عندما يحذف المستخدم التطبيق، يستمر السيرفر في محاولة إرسال إشعارات لتوكنات ميتة مما يستهلك الذاكرة والـ API Quota.
* **الحل المنفّذ في Clan App**:
  * عندما يرد خادم FCM برمز `404` أو `UNREGISTERED` أو `INVALID_ARGUMENT`، يقوم السيرفر تلقائياً بحذف توكن الجهاز من جدول `Device` في نفس اللحظة:
```javascript
if (response.status === 404 || errCode === 'UNREGISTERED' || errCode === 'INVALID_ARGUMENT') {
  log.warn({ fcmToken }, '🗑️ حذف توكن جهاز ميت/ملغي تثبيت التطبيق');
  await prisma.device.deleteMany({ where: { fcmToken } });
}
```

## ٤. وضع المحاكاة الذكي للتطوير (Sandbox Fallback Mode)

* في بيئة التطوير والاختبارات التلقائية عند غياب ملف الاعتماد السحابي، يعمل المحرك بنمط **`MOCK_DISPATCH`** الآمن؛ يسجل الإشعار ويوثق خروجه في قاعدة البيانات ويمنع انهيار السيرفر.
