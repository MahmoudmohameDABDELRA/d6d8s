## 3) مخطط الجداول (Prisma) — بالتفصيل

```
Goal (موجود — الحلم/الجبل)
 └── GoalStep (موجود — الأهداف/المراحل)
      │     + durationWeeks Int?     ← من JSON المرحلة 1 (مدة الهدف بالأسابيع)
      └── GoalStepJourney (🆕) — رحلة الهدف (واحدة لكل خطوة — unique)
            │  goalStepId unique · title · durationDays
            │  currentDay Int @default(1) · status DRAFT→ACTIVE→COMPLETED
            │  rebuildProposal Json? ← مقترح إعادة البناء (21→35) قبل الموافقة
            ├── JourneyDay (🆕) — أيام الرحلة
            │     journeyId · dayNumber (1..N) · title · description?
            │     durationMin? · subTasks Json? ← مهام اليوم (1-3) من الـ AI
            │     scheduledDate @db.Date? · status PENDING→COMPLETED · completedAt?
            │     @@unique([journeyId, dayNumber]) ← ترتيب صارم
            │     task Task? ← علاقة بالمهام (المولدة)
            └── JourneyMastery (🆕) — تقييم "تعلمت صح"
                  journeyId unique · questions Json (مع الإجابات الصحيحة المخفية)
                  score Int? · passed Boolean? · attempts Int · status

Task (تعديل — جدول المهام الموجود)
  + source String @default("MANUAL")      ← MANUAL | JOURNEY
  + journeyDayId String? (مفهرس)          ← اليوم اللي اتعملت منه
  + goalStepId String?                    ← الهدف/المرحلة
  (المهام اليدوية زي ما هي — source=MANUAL)
```

**ملاحظة مهمة**: اليوم الواحد ممكن يولّد **أكثر من Task** (مثال يوم 4: تعلم Loops + حل 10 أمثلة + Quiz) — عشان كده `journeyDayId` مش unique، والـ Scheduler يعمل Task لكل `subTask`.

## 5) شرح برمجة كل وظيفة (بالطريقة التقنية)

### 5.1 توليد رحلة الهدف — `journeyPlanner.generateJourney()`
```
1) نداء Gemini واحد بنفس نمط dreamPlanner:
   system prompt: "مخطط الرحلات — ابنِ خطة يومية لهدف واحد.
                   {days:[{day, title, description, durationMin, tasks:[1-3]}]}"
   prompt JSON: {goal, durationWeeks, dreamTitle}
   التوليد: gemini.service.generate(system, [], prompt, {maxTokens: 2048, temperature: 0.7})
2) extractJson + تحقق من الشكل:
   - أيام ≥ 1 · dayNumber متسلسل من 1 · title نص
   - لو الشكل غلط → إعادة نداء مرة واحدة (maxRetry=1) → لو لسه غلط → 503 صادق
3) تخزين في **transaction واحدة**:
   prisma.$transaction([
     goalStepJourney.create({goalStepId, title, durationDays: days.length}),
     journeyDay.createMany({days})
   ])
   → حالة DRAFT (مش ظاهرة في أي مكان حتى الموافقة)
4) يرجع {journeyId, days} للمعاينة
```
**نفس الطريقة لـ Mastery Generator**: نداء AI واحد يولّد `{questions:[{q, options[4], answerIndex}]}` — التصحيح بعدين **محلي صفر AI** (نقارن index) — أسرع وأرخص وثابت.

### 5.2 تفعيل الرحلة — `approve`
```
1) تحقق: journey ملك المستخدم + DRAFT (404/409)
2) transaction:
   - journey → ACTIVE + currentDay=1
   - توزيع scheduledDate: يوم 1 = النهارده، يوم 2 = بكرة، ... (حساب تاريخي خالص)
   - إلزامي: الخطوة لسه مش مكتملة (الترتيب)
3) استدعاء الـ Scheduler فوراً → يخلق مهام اليوم 1 في جدول Tasks
```

### 5.3 الـ Scheduler اليومي — `journeyScheduler.runDaily()` (صفر AI)
```
1) BullMQ Job متكرر: cron "0 6 * * *" (كل صباح 6) + استدعاء إضافي عند فتح التطبيق (login hook)
2) يقرأ كل journey ACTIVE:
   - day = JourneyDay حيث dayNumber = journey.currentDay
   - لو day.status = PENDING:
        - لو في Task موجودة بـ journeyDayId → سكيب (Idempotent — منع تكرار)
        - وإلا → Task.create لكل subTask (أو يوم واحد من العنوان لو مفيش)
             { title, description, source:'JOURNEY',
               journeyDayId, goalStepId, scheduledDate: اليوم,
               priority:'GROWTH', estimatedMin: day.durationMin }
3) إشعار واحد: "النهارده عندك: [مهام اليوم]" (Notification)
```

### 5.4 سلسلة التقدم عند «تم الإنجاز» — `journeyProgress.completeDayChain()` (صفر AI)
```
لما Task بتتكمّل في task.controller (الموجود):
   لو task.source = 'JOURNEY':
   prisma.$transaction([
     task.update(isCompleted)          ← الخطوة 1 (موجودة)
     journeyDay.update(status=COMPLETED, completedAt)   ← الخطوة 2
     journey.update(currentDay = اليوم اللي بعده PENDING) ← الخطوة 3 (فتح اليوم الجديد)
   ])
   - لو كل الأيام COMPLETED:
        journey → COMPLETED
        → نداء الـ Mastery (توليد أسئلة) → Notification "اتعلمت؟ جاوب على 3 أسئلة"
   - جدولة checkin: BullMQ job مؤجل 10 دقايق
```

### 5.5 التعليم على الإتمام — Mastery
```
1) POST mastery → AI يولّد {questions[4] مع answerIndex} → تُحفظ (الأجوبة الصحيحة مش بترجع للفرونت)
2) POST submit {answers:[index...]} → تصحيح محلي:
   score = صح/4 · passed = score ≥ 0.6
   - PASSED → journey COMPLETED نهائياً → استدعاء نفس منطق completeGoalStep الموجود
             → GoalStep يكتمل → الجبل يطلع للحقل اللي بعده
             → ولو ده آخر حقل → الهدف كله يكتمل (القمة 🏁 — completedAt)
   - FAILED → محاولة تانية (attempts+1) + AI يقترح مراجعة اليوم اللي ضعيف فيه
```

### 5.6 إعادة البناء الذكية — `journeyAdapt` (Follow-up Coach)
```
1) في الـ daily job: لو journey ACTIVE و عدد أيام متأخرة (قبل currentDay ومش مكتملة) ≥ 3:
2) نداء AI واحد:
   prompt: {goal, remainingDays, daysCompleted, streak, overdueTasks}
   → AI يرجع {newDays:[...]} للأيام المتبقية بمدة أطول (21→35)
3) يُحفظ في journey.rebuildProposal (JSON) → Notification:
   "الرحلة اتعاد بناؤها 35 يوم بدل 21 — اعرض ووافق"
4) المستخدم يوافق (rebuild/approve) → transaction:
   - حذف أيام PENDING القديمة + إنشاء الجديدة (مرقمة من currentDay)
   - currentDay ثابت · scheduledDate تتوزع من النهارده
   - رفض → يتجاهل (وممكن يرجع يقترح بعد 5 أيام)
   لو أسرع (أنهى قبل الموعد) → نفس الآلية بضغط (مقترح أقصر) — بنفس مسار الموافقة
```

### 5.7 بروتوكول المهام الكامل (نكشة + Popup + اطمئنان)
```
- نكشة قبل 5د: موجود ✅ (taskNudge — يشتغل على كل المهام لأنها نفس الجدول)
- Popup وقت المهمة: فرونت (يُبنى لاحقاً — الباك بيبعت Notification بالوقت)
- اطمئنان بعد 10د (🆕 taskCheckIn):
   1) عند إنجاز أي مهمة (يدوية أو مولدة) → BullMQ delayed job 10 دقايق
   2) executeCheckIn: نداء Gemini بـ persona TASK_FOLLOWUP (جاهزة في aiPersona:131)
      → "عملت إيه يا بطل؟ قولي اللي حصل" → Notification
   3) المستخدم يرد (checkin-reply) → AI يحلل المشاعر:
      فرحان → تحفيز · زعلان → احتواء + "هل أقترح حلول؟" · مأنفذش → صفر لوم + خطوة صغيرة
      → الرد يتخزن في AiConversation (ذاكرة دائمة)
```

### 5.8 النظام المرن — شارة «متأخر N»
```
- مش قفل: اليوم الجاي دايماً مفتوح
- حساب لحظي (لا تخزين): في GET الجورني
  lateDays = عدد أيام قبل currentDay بحالة PENDING
  → يظهر شارة "متأخر N يوم" في الفرونت
- إعادة البناء بتتعرض كاقتراح — موافقة المستخدم إلزامية (مبدأ الدستور)
```

## ⚠️ النسخة النهائية المعتمدة (2026-08-13) — تحل محل كل ما سبق من تصميم

### الجداول (5 فقط — قرار المالك النهائي)
| الجدول | التعديل |
|--------|---------|
| Goal | **صفر تعديل** (draft/isActive/completedAt كافية) |
| GoalStep | **صفر تعديل** (order/isCompleted/completedAt كافية) |
| Journey 🆕 | goalStepId unique · title · durationDays · currentDay=1 · status (DRAFT/ACTIVE/COMPLETED) · approvedAt · completedAt |
| JourneyDay 🆕 | journeyId · dayNumber · title · description · scheduledDate · status (PENDING/COMPLETED) · completedAt · @@unique([journeyId, dayNumber]) |
| Task | + source ("MANUAL"/"JOURNEY") · + journeyDayId (مفهرس) |

### المحذوف نهائياً من النسخة النهائية
- ~~JourneyMastery~~ (لا كويز تقييم — الهدف يكتمل بإنهاء أيامه)
- ~~rebuildProposal~~ (لا إعادة بناء 21→35 في المرحلة الأولى)
- ~~ARCHIVED/SUPERSEDED~~ (لا حاجة — رحلة واحدة لكل هدف)

### الثابت من المراجعات (P1/P2/P3 + المرونة)
- اليوم COMPLETED ⟺ كل Tasks المولدة منه isCompleted (اليدوية لا تُحتسب)
- توليد Lazy عند فتح التطبيق (timezone المستخدم) + Cron شبكة أمان · Idempotent بـ @@unique
- اليوم الجاي مفتوح دايماً + «متأخر N» محسوبة لحظياً

### تدفق التنفيذ (8 مراحل — كلها على النسخة دي)
المستخدم يكتب الحلم ← (موجود) AI: steps → Goal/GoalStep ← موافقة ← ضغط هدف ← (جديد) AI: days → Journey DRAFT ← موافقة → ACTIVE + scheduledDate ← (جديد صفر AI) Scheduler: JourneyDay[currentDay] → Task في المهام ← "تم الإنجاز" (موجود+تعديل): Transaction واحدة Task→Day→Step ← (جديد) checkin مؤجل 10د ← آخر يوم → GoalStep ✓ ← أول خطوة غير مكتملة = النشط (بلا AI) ← آخر خطوة → Goal.completedAt 🏔️ (موجود)

## 🔒 القواعد الصارمة للتنفيذ (أمر المالك — 2026-08-13)

1. **صفر وهمي نهائياً** — ممنوع أي كود شكلي أو بيانات Hardcoded أو شاشة من غير ربط. أي ميزة = UI → API → Service → DB → AI كاملة.
2. **التحقق من التوصيل في كل مرحلة** — كل مرحلة (M1..M7) مش بتعتبر "خلصت" إلا بدليل حي فعلي يثبت الربط:
   - Schema → `prisma db push` + فحص الجداول في القاعدة
   - Service AI → نداء Gemini حي يرجع JSON صحيح (مش محاكاة)
   - API → تجربة live على السيرفر الشغال (curl/سكربت حقيقي)
   - سلسلة الإنجاز → مهمة حقيقية بتتكمّل → اليوم والخطوة والجبل بيتحدثوا في القاعدة
   - Queues → الجوب يشتغل فعلاً ويخلق Task في الجدول
   - الاختبارات → `mountain-lifecycle.test.mjs` كامل أخضر + الـ 48 القديمة لسه خضراء
3. **لا كويز إطلاقاً** (قرار المالك النهائي) — الهدف يكتمل بإنهاء كل أيام رحلته، من غير أي تقييم/اختبار.
4. لو حاجة مش قادرة تتوصّل (مثلاً Gemini معطل) → خطأ صريح صادق (503) مش إخفاء — زي نمط `GEMINI_NOT_CONFIGURED` الموجود.
